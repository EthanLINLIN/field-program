# AI 安装与调试指南：Linux

本指南适用于用户要求 AI 自动安装、运行或调试本项目的情形。以用户的具体要求和运行环境权限为准；不要因为阅读了本文件就自动操作。请先读取本文件、`README.md` 和 `THIRD_PARTY_NOTICES.md`。如果用户交付的是包含 Windows、Linux 两个目录的完整公开版，先识别操作系统，再进入对应目录；不要把 Windows 目录当作 Linux 版本运行。

## 1. 检查环境

- 确认当前系统为 Linux，并在本文件所在目录执行以下命令。确认项目已经放在最终使用位置；移动已安装的项目后需要重建或修复 `.venv`。
- 检查 Python 3.11、venv、pip、系统架构和可用磁盘空间。使用 `python3.11 --version` 或 `python3 --version`，并用 `uname -m` 检查架构；当前依赖主要面向 Linux x86-64。若 Python、venv 或系统图形库缺失，依据发行版及用户授权范围处理；需要额外权限或受限时说明阻碍，不要声称安装成功。
- 安装 Python 依赖和首次下载模型需要访问网络。FERPlus 上游的 MIT/Apache-2.0 标注存在冲突，来源及范围见 `THIRD_PARTY_NOTICES.md`；下载不意味着该冲突已解决。

## 2. 安装

在本目录执行：

```bash
bash setup.sh
.venv/bin/python -m pip check
```

`setup.sh` 要求 Python 3.11，创建 `.venv` 并安装 `requirements.txt`。确认两条命令均成功；已有环境可用时，先检查再决定是否重新创建。不要删除用户数据或覆盖不相关的环境。依赖安装失败时查看完整错误，针对实际问题修复并复测。

## 3. 软件验证

1. 检查 `127.0.0.1:5050` 和 `127.0.0.1:8080` 是否被占用；不要结束不属于本次任务的进程。端口冲突时查明并向用户报告。
2. 使用 `bash start.sh --no-esp32 --no-browser` 启动本次验证的服务，保留进程及输出。该命令不会启动 ESP32 控制器或自动打开浏览器，也可在非交互环境运行。首次运行将从上游下载 FERPlus 到项目目录外的缓存，并校验 SHA-256；失败时检查网络、缓存路径及错误信息。不要绕过哈希校验或声称真实下载成功，除非已实际验证。
3. 分别检查 `http://127.0.0.1:5050/`、`http://127.0.0.1:5050/api/state`、`http://127.0.0.1:5050/api/field-emotion/latest` 和 `http://127.0.0.1:8080/display/opening_ui_eeg_motion.html` 返回正常；必要时检查 `display/videos/` 中三个视频资源。核对服务确实由本次启动的进程提供，避免把其他服务误判为通过。
4. 按请求保留运行中的服务，或通过受控的 Ctrl+C 停止本次启动的启动器并确认其子进程退出；不要强制终止其他应用。报告实际做过的检查及结果。

## 4. 硬件边界与结果

- 默认只执行软件验证：不连接或占用 ESP32 串口、不烧录或擦除固件、不触发 GPIO、水泵或雾化器，也不启动摄像头采集。硬件识别和实体动作需要用户明确提出后再进行。
- 如果用户明确要求硬件联调，先核对串口、设备权限、已烧录固件、供电及实际接线，再按用户授权和 README 操作。正常硬件流程需在启动终端输入 `2`、`5`、`8` 或 `q` 并回车；不要把这些命令误当成全局热键。真实设备未接入、摄像头未检查或未执行 GPIO 动作时，应分别标明未验证，不能由模拟结果推断实机通过。
- 如果需要用户提供缺失信息或系统权限，先完成不依赖该信息的检查，再说明具体阻碍。报告系统、安装结果、模型下载或缓存结果、接口检查、硬件检查范围、服务状态及尚未解决的问题。
